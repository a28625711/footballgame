### 联赛现实化重调（2026-08-29）

**问题**：原强度公式 `rep×20+随机±15` 差距过大 → 高rep队夺冠~100%（西甲皇马/巴萨垄断、法甲PSG垄断、无爆冷）。

**修复**：
1. **强度公式**：`rep×20 → rep×11`，随机 `±35`（差距缩小，爆冷合理）
2. **夺冠**：第1名 `ca=0.9`（排名即决定冠军，不再双算竞争）
3. **玩家加成**：`ovr×(2+2×角色)/130`（核心95约+7，替补约+2）

**已验证夺冠分布（大样本模拟，无玩家）**：
| 联赛 | 现实对照 | 游戏 |
|---|---|---|
| 西甲 | 皇马/巴萨各~40% | 各~39% ✓ |
| 英超 | 曼城/利物浦/阿森纳三强 | 各~26% ✓ |
| 法甲 | PSG ~80% | ~69% ✓ |
| 德甲 | 拜仁~70%，多特/勒沃各~15% | 拜仁~54%，各~15% ✓ |
| 意甲 | 国米/尤文/米兰/那不勒斯 | 国米~49%，各~12% ✓ |
| 中超 | 海港/泰山/申花 | 各~24% ✓ |

**玩家加成效果（皇马，西甲2强）**：
- 低OVR主力：夺冠47%（≈无玩家40%基线）
- 中OVR主力：52%
- **高OVR核心(95)：57%** ✓（符合50-60%目标）
- 替补：44%

**数据核查**：西甲2×rep5+马竞rep4 ✓，英超3×rep5（曼城/利物浦/阿森纳）+3×rep4 ✓，法甲PSG rep5 ✓，中超3×rep3 ✓（用esprima正确解析，此前正则漏了混合引号）

### 联赛模拟混合旧方案（2026-08-29）

**分析**：旧方案（git原版）用`TROPHIES`表按球队rep给冠军概率 + `cmr/ctn`（联赛max-rep队数=联赛整体强弱）。当前OVR排名方案忽略了联赛整体强弱 → 英超第1和中超第1胜率一样。

**混合**（保留"排名→W/D/L"，引入联赛rep强度）：
- `_diff = (联赛rep-2)/3`（英超1/德甲0.67/中超0）
- **排名随机性**：`±15×(1+_diff)` → 强联赛爆冷更多（英超±22，中超±15）
- **W/D/L均衡**：`_lw -= _diff×0.04, _ld += _diff×0.02` → 强联赛第1名胜率73%→69%
- **夺冠概率**：`rank1 ? (0.94 - _diff×0.06) : ...` → 英超88%，中超94%
- 球队所在强弱（rep）+ 玩家OVR角色加权 → 排名（保留）

**验证**：曼城第1=英超冠军，转会利雅得新月第1=沙特联冠军（机制正确）；不同联赛W/D/L明显区分

#### 第二步：杯赛 + 国家队赛事统一框架（已完成 ✅）

**设计原则**：两套可复用的模拟逻辑，覆盖所有杯赛/国家队赛事。

##### 逻辑 A：小组赛模拟（groupStage）

适用于：世界杯小组赛、亚洲杯小组赛、世预赛小组赛、欧预赛小组赛等。

**输入**：
```
playerTeam: { name, rep, ovr }
opponents: [ { name, rep }, { name, rep }, { name, rep } ]  // 同组3队
```

**模拟流程**：
1. 玩家球队 vs 每个对手各赛一场（共3场）
2. 对手之间也互赛（共3场）→ 用于确定小组排名
3. 每场比赛根据双方 rep + ovr 差异模拟比分
4. 计算积分榜（3分制），前2名晋级

**单场比分模拟**：
```
attStrength = f(team.rep, team.ovr)  // 进攻实力
defStrength = f(opp.rep, opp.ovr)    // 防守实力
goalDiff = attStrength - defStrength + random波动
teamGoals = max(0, round(avgGoals + goalDiff/2))
oppGoals = max(0, round(avgGoals - goalDiff/2))
```

**输出**：
```
{
  matches: [ { home, away, hg, ag } ],   // 6场比赛结果
  standings: [ { team, pts, gf, ga } ],   // 积分榜
  playerTeamPos: 1-4,                      // 玩家排名
  advanced: [ team1, team2 ]               // 晋级的2队
}
```

##### 逻辑 B：淘汰赛模拟（knockoutStage）

适用于：世界杯淘汰赛、亚洲杯淘汰赛、国内杯赛、超级杯等。

**输入**：
```
bracket: [ [teamA, teamB], [teamC, teamD], ... ]  // 对阵表
// 淘汰赛从16强/8强/4强/决赛逐轮推进
```

**模拟流程**：
1. 每轮配对，每对模拟一场比赛
2. 胜者进入下一轮
3. 玩家球队所在的半区正常推进
4. 非玩家球队的半区也模拟（但只记录比分，不展开细节）
5. 直到决出冠军

**单场模拟**：同小组赛的单场逻辑，但加时/点球概率略高（决赛压力）

**输出**：
```
{
  rounds: [
    { name: "十六强", matches: [ { home, away, hg, ag } ] },
    { name: "八强",   matches: [ ... ] },
    { name: "四强",   matches: [ ... ] },
    { name: "决赛",   match: { home, away, hg, ag } }
  ],
  champion: "巴西",
  playerTeamStage: "四强"  // 玩家止步哪轮
}
```

##### 框架复用关系

| 赛事 | 小组赛 | 淘汰赛 | 备注 |
|------|--------|--------|------|
| 世界杯 | 逻辑A：8组，玩家只模拟所在组 | 逻辑B：16强→8强→4强→决赛 | 小组前2晋级 |
| 亚洲杯 | 逻辑A：6组，玩家只模拟所在组 | 逻辑B：16强→...→决赛 | 小组前2晋级 |
| 世预赛（亚洲） | 逻辑A：分组主客场 | — | 前N名出线 |
| 世预赛（欧洲） | 逻辑A：分组 | 逻辑B：附加赛 | 前N名+附加赛 |
| 欧洲杯 | 逻辑A：6组 | 逻辑B：16强→... | 小组前2+4个最佳第3 |
| 国内杯赛 | — | 逻辑B：单场淘汰 | 从第3轮开始 |

- 世界杯：玩家所在组的第2名 → 对阵另一组的第1名（真实对阵规则）

##### 球队抽选规则（已确认）

- 世界杯/亚洲杯：**按 rep 分种子档，同档不同组**（模拟真实抽签）

  - 亚洲区：按 rep 分档分组，组内循环（逻辑A）

## 二、核心发现：混淆机制

所有 7 个 JS 文件都经过了 **javascript-obfuscator** 混淆（字符串数组 + base64 自定义字母表 + 数组旋转）。

### 混淆结构（每个文件独立一套）

```js
// 1. 字符串数组：元素是 base64 编码
function _xxx_0a() { var gW=[...]; return ...; }

// 2. 解码器：base64 + %XX + decodeURIComponent
function _xxx_0b(a,b){ a=a-0x偏移; var c=_xxx_0a(); var d=c[a]; ... }

// 3. 旋转循环：数组 shift 直到公式匹配目标值
(function(a,b){ ... if(d===b)break; else c['push'](c['shift']()); }}(_xxx_0a,0x目标))
```

| 文件 | 解码偏移 | 数组元素数 | 旋转目标值 | 旋转次数 |

## 三、遇到的坑（问题记录）

### 坑 1：PowerShell 编码问题
本环境是 Windows PowerShell 5.1，命令行的中文字符和特殊字符经常乱码。**解决方案**：所有逻辑写成 `.py` 脚本文件再执行，避免 `py -c "..."` 内联传参。

### 坑 2：base64 字母表差异
最初用 Python 标准 `base64.b64decode` 解码全部报 UTF-8 错误。原因是混淆器用了**自定义字母表**（小写在前）。**解决方案**：`str.maketrans` 映射回标准表再解码。

### 坑 3：数组旋转未收敛
`game.js` 旋转公式里 `parseInt` 遇到非数字片段返回 NaN，初版模拟死循环。**解决方案**：发现旋转是"每次 shift 一个元素 + 重新解码检查"，最终 brute-force 在 337 次收敛。

### 坑 4：图片路径是拼接出来的
队徽/奖杯路径不在字符串里，而是由切碎的片段拼接（`'assets/c'`+`'rests/cn'`+`'-jing.we'`+`'bp'` = `assets/crests/cn-jing.webp`）。且路径是**平铺单层**（`assets/crests/{id}.{ext}`），不是 `assets/crests/cn/{id}` 子目录。

### 坑 5：Cloudflare Pages SPA fallback
第一次下载队徽时全部返回 13.6KB 的 HTML（fallback 到 index.html），误以为下载成功。**验证方法**：检查文件魔数（PNG 应为 `\x89PNG`，WEBP 应为 `RIFF...WEBP`），并检查 Content-Type 是否 `text/html`。
