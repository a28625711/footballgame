# 足一把·生涯模拟器 —— 事件文案润色任务

## 一、这是什么

这是一个足球球员生涯模拟游戏的中文文案。你是一位文字编辑，任务是把下面 JSON 里的**每一条**事件文案润色得更有文学味道，同时遵守严格的规则。

游戏视角：以「你」为主人公，用第二人称讲一个足球运动员一生的故事。玩家阅读这些文案时，会出现在游戏卡片上，每段通常 1~3 句话。

## 二、润色目标

原文整体偏"简洁直白"，像新闻播报。请把它改成：**克制、有画面、有情绪余味**的文学性短叙事。具体风格参考：

- 多用具体细节代替抽象概括（"更衣室里没人再质疑谁是主力" 可以更有画面感，但不要变长）。
- 留白：把情绪藏在动作和细节里，不直说"他很失落"。
- 短句有力，适当用一点对仗/重复/留白，但**不要堆砌形容词**，不要用网络段子腔。
- 每段仍以「你」为主角，保持第一/第二人称叙事（原文都用"你"）。

**长度控制**：保持原文长度附近，可增减约 30%，不要扩写成一大段。1~3 句为宜。

## 三、硬性规则（违反会直接判废）

1. **不准改数值**：能力点、概率、比分、时间、金额、赛季轮次（如"第 31 轮""第 78 分钟""0 比 2"）等数字必须原样保留。
2. **不准改事件机制含义**：选择对应的后果（谁上场、谁被换下、谁受伤、钱变多还是变少）方向不能改。
3. **占位符原样保留**：`{club}` `{rival}` `{league}` 这些花括号占位符必须一个字符不改。
4. **人名/队名/地名**：原文出现的外国人名（如"梅西""哈兰德""莫德里奇"）、城市、联赛名，原样保留，不要改成别的。
5. **不要加 emoji**，原文没有就别加；原文引号（「」和""）风格尽量保留。
6. **不要改语气之外的语义**：不做价值判断的删除，不新增没有依据的情节。

## 四、字段说明与润色重点

每条 JSON 长这样：
```json
{"id": "S0042", "event_id": "extra_training", "event_title": "加练",
 "scope": "generic", "field": "desc",
 "original": "队里加了一期封闭集训，教练问你要不要跟着上强度。",
 "polished": ""}
```

- `field` 取值：
  - `desc` = 事件开头描述（重点润色）
  - `title` = 事件标题，**保持 2~8 字的短语风格**，可略润色
  - `label` = 玩家可点的选项按钮，**保持 2~10 字短语**，不要写成句子
  - `text` = 选择后的结果叙事（重点润色）
- `scope` 取值（**极重要**，见下条）
- `occ` = 这条原文还出现在哪些事件里（同一句可能在多个事件复用，润色一次即可全站生效）

## 五、scope 范围规则（关键）

- **`generic`（通用）**：这个事件在**任何国家的联赛**都会触发。润色后文案里**绝对不许出现中国特色的东西**：火锅、涮、烤串、饺子、年夜饭、春晚、除夕、红包、麻将、白酒劝酒、体测（YOYO/12分钟跑）、微博热搜、中超、足协、微信/QQ群等。改成全世界任何俱乐部都成立的说法。
- **`abroad`（出国）**：场景在**外国**，主人公是中国球员。允许他本人的中国元素（过年想家、煮饺子、学外语、亚洲超市），但**不允许出现中国体制/机构味**（足协、体测、编制、U23政策等），因为场景在外国。
- **`china`（国内）**：纯中国场景，中国特色随便用，但要润色得好。

## 六、输出格式（必须严格遵守）

对每一个 `part_XX.json`，输出一个 JSON 对象，结构如下：

```json
{
  "revisions": [
    {"id": "S0042", "polished": "队里加了一期封闭集训。教练把名单贴出来那天，问你一句要不要跟着上强度。"},
    {"id": "S0151", "polished": "营养师"}
  ]
}
```

要求：
1. **必须覆盖输入里的每一个 `id`**，一个都不能漏。
2. `polished` 填润色后的完整文本；如果某条你觉得已经很好、不想改，就原样抄回原文。
3. 只输出这一个 JSON 对象，不要输出别的解释文字。
4. 原样保留原文里的引号、破折号等标点习惯。

## 七、工作流

1. 把本文件 + 某个 `part_XX.json` 一起喂给 AI。
2. AI 返回 `{"revisions": [...]}`，保存为 `part_XX_done.json`。
3. 把所有 `part_XX_done.json` 拿回来，我会合并注入 `events.deob.js`。

## 八、润色样例（风格基准）

同一类原文 → 三种写法：一般 / 更好 / 最好。目标至少达到「更好」，尽量到「最好」。

**desc（开头描述）**
- 原："队里加了一期封闭集训，教练问你要不要跟着上强度。"
- 更好："队里加了一期封闭集训。教练把训练表贴出来那天，单独问你一句：要不要跟上。"
- 最好："队里加了一期封闭集训。名单贴出来的第二天，教练在更衣室堵住你，只问了一句话。"

**text（结果叙事）**
- 原："一整期练下来，体脂降了，触球也稳了。教练开始在战术板上写你的名字。"
- 更好："一整期下来，体脂降了，触球也稳了。战术板上，你的名字出现得越来越勤。"
- 最好："一整期下来，体脂降了，触球也稳了。没有掌声，只是战术板上的那个十号位，笔画渐渐成了你的。"

**text（负面结果）**
- 原："第三周就练伤了。躺了两个月，回来时位置已经是别人的。"
- 更好："第三周就练伤了。躺了两个月，回来才发现，自己的位置早就坐了别人。"
- 最好："第三周就练伤了。两个月病床把一切都换掉了——再回来，首发名单上没有你的名字。"

**label（按钮）**：只能 2~10 字短语，能动性即可，不必多改。
- 原："上" → "跟上强度"；原："按计划来" 保留即可。

**title（标题）**：2~8 字短语，微调即可，不是重点。
- 原："加练" → 保留；原："捡了只狗" → "基地来客"（可以略加画面，也可不改）。

**abroad 示例**（场景在国外，去掉中国体制味）：
- 原："你在家待了九天。回来的时候体测掉了一档，教练什么也没说，只是把你那组换到了后面。"
- 改："你在家待了九天。回来时体能掉了一档，教练什么也没说，只是把你那组换到了后面。"（体测→体能）

**china 示例**（中国场景，中国特色可用）：
- 原："春节前最后一场主场比赛，俱乐部安排球迷在开场前拉了一条横幅。"
- 改："大年二十九那场主场比赛，开场前，看台上拉开一条横幅，字是球迷自己写的。"
